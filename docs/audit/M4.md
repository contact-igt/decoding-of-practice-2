# M4 · Attribution, analytics and search

The local page queues event-only analytics payloads and keeps campaign attribution in the browser session through the enquiry. The event payload contains placement, variant, step, item or a random enquiry event ID as applicable. Form values and referrer paths stay out of these events. The intake receives first and latest campaign touches, a referrer origin, five UTMs and allowed Google/Meta click IDs when present.

| Event area | Event names |
| --- | --- |
| Page and enquiry CTAs | `page_view`, `hero_cta_click`, `admission_cta_click`, `phone_click`, `whatsapp_click` |
| Exploration | `curriculum_view`, `module_expand`, `case_stage_expand`, `brochure_request`, `brochure_download`, `mentor_video_play`, `testimonial_video_play` |
| Form and conversion | `admission_form_start`, `admission_form_step_complete`, `admission_form_submit`, `admission_lead_success` |
| Local acceptance | `dop_local_test_success` is separate from the live event. |

The live event fires after server acknowledgement, with a stable event ID, once per successful client request. The confirmation route emits no conversion, including on refresh. For approved future Meta CAPI, send that same event ID with the matching mapped event name. Reconcile raw enquiry, qualified lead and paid admission in the CRM before importing downstream conversions.

Optional GTM loading is gated by an explicit visitor choice and a configured container ID. **BLOCKED** for production tag activation and validation. Configure authorised GA4, Google Ads, Meta and Clarity tags inside the approved container, apply consent gates to every tag, disable duplicate automatic page-view mappings, scrub URLs and query values, mask inputs, and check mappings in an isolated property. Confirm retention and consent wording with the owner. There is no Meta CAPI transport or production test traffic.

## Meta Pixel PageView tag

The programme page loads Meta Pixel 1320569916265124 directly after analytics opt-in and queues one PageView per document. Before publishing, confirm the GTM container has no PageView tag for this pixel and verify URL and referrer handling in an isolated setup. The image fallback is omitted so tracking follows the site's JavaScript consent flow.

The programme renders server-side with title, description, canonical URL, social image and Course, EducationalOrganization and BreadcrumbList data. Preview metadata is noindex, robots denies crawling and the preview sitemap has no programme entry. Approved-origin plus indexing enablement publishes a canonical sitemap. The confirmation page stays noindex.

Files are `lib/analytics.ts`, `components/tracking.tsx`, `lib/site-url.ts`, `app/robots.ts`, `app/sitemap.ts` and page metadata.
