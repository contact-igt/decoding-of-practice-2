# M3 · Admission intake

The loopback test flow accepts synthetic data in process memory and labels the confirmation as a test. Production intake is **BLOCKED** on a verified and authorised endpoint. A disabled or unavailable transport returns a visible error.

## Contract

- POST JSON to `/api/dop-enquiry` with a UUID v4 `Idempotency-Key`. The server checks origin when supplied, body size, honeypot, permitted form values, phone formatting and explicit contact consent.
- The production adapter uses one HTTPS endpoint with server-only bearer and receipt secrets, a six-second timeout and redirect rejection. Forward the same idempotency key on user retry. The destination must enforce stable deduplication across processes, persist the lead and return a 2xx JSON body with `{"accepted": true}`.
- The server coalesces concurrent requests within a process, limits requests per incoming connection and phone hash, and issues an HttpOnly signed receipt that expires after 15 minutes. Confirm trusted ingress headers and gateway limits for the release environment. The current per-process limiter is supplementary.
- The local adapter is off unless explicitly enabled on loopback with indexing off. No names, numbers, messages or credentials appear in app telemetry. The webhook receives the approved contact fields, consent version, variant and bounded first/latest campaign fields.

Files are `app/api/dop-enquiry/route.ts`, `lib/enquiry.ts`, `lib/receipt.ts`, `app/decoding-of-practice/thank-you/page.tsx`, `.env.example` and unit/browser checks. See [M5](M5.md) for exercised outcomes.
